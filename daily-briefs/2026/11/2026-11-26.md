### 1. DFly2：共享目标模型的稀疏选择，降低长上下文推测解码开销

[论文原文](https://arxiv.org/abs/2611.34776v1)。作者提出块并行草稿模型，同时复用目标模型的 KV 缓存与稀疏索引选择，避免草稿模型维护独立上下文缓存或额外执行位置评分。摘要报告，在所比较的稀疏模型与任务上，该设计提高每步接受的草稿 token 数，并改善长上下文及 Agent 工作负载的吞吐。

**关注点：** 优化的不仅是草稿质量，还有缓存、索引计算与并发成本。收益依赖目标模型架构、稀疏模式及部署配置，不能泛化为任何模型的固定加速倍数。

### 2. Mixture-of-Loops Transformer：以 KV 记忆连接循环计算

[论文原文](https://arxiv.org/abs/2611.34923v1)。作者将 KV 作为可跨深度、跨循环选择复用的记忆，比较保留残差流与从 embedding 重启的循环方式；进一步提出 U 形结构，将记忆构建和预测读取分离，减少不需要的解码遍历。摘要报告，其预训练与继续预训练实验在所比较配置下改善 token 效率及质量。

**关注点：** 为共享参数的循环模型提供兼顾表达力与推理效率的架构路线。摘要给出[代码入口](https://github.com/hustvl/MoLT)，但本期仅确认论文今天首次提交，不将代码仓库或模型权重开放时间另算作今日发布。

### 3. RoboEvo²：执行框架与机器人策略互相改进

[论文原文](https://arxiv.org/abs/2611.34675v1)。策略失败驱动编程 Agent 搜索修复方案，将验证成功的解法沉淀为技能、路由与经验记忆；成功轨迹和同起点下的成功／失败对比再用于训练策略，由改进后的策略支持下一轮搜索。摘要报告该循环无需额外人类示范，在所测试的仿真及机器人任务上改善成功率并降低 Agent 开销。

**关注点：** 将推理发现新技能与策略高效执行连接起来。作者写明模型与代码“将公开”，本期不将其描述为已经开放下载，也不把论文结果推及任意真实环境。

### 4. 编程 Agent 是否过度修改：用可回放补丁归因代替单纯比较行数

[论文原文](https://arxiv.org/abs/2611.34875v1)。作者提出 Delta Residue Attribution，回放 Agent 轨迹、追踪补丁单元来自哪一步，逐单元撤销修改并重跑任务测试，从而估计修改是否必要。摘要指出，Agent 补丁较大并不自动等于代码过度修改，额外变化可能来自测试与文档；同时，依然存在改变行为却非必要的代码修改。

**关注点：** 对编程 Agent 评测和代码审查，应将修改必要性与任务解决率并列考察。依赖现有测试判断必要性有覆盖盲区，作者也报告补丁裁剪可能误删必要代码，不宜直接将其当作无风险自动清理工具。

### 5. 微调后门检测：权重、激活与输出差异各有盲区

[论文原文](https://arxiv.org/abs/2611.34758v1)。作者使用基于 token 读出的统一评分体系，比较权重、激活与输出层面的模型差异检测，并引入 J-lens 与 J++-lens 改进读出。摘要报告，某些训练方式可以绕过输出／激活检测，而隐藏单元置换等方式又可削弱权重差异检测；没有单一方法抵御文中两类规避方式。

**关注点：** 对微调模型供应链审计，应结合多种检测视角；论文不支持“单一权重扫描即可排除所有后门”的结论。
